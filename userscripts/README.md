# プライスター・購入上限30個（ユーザースクリプト）

プライスターの商品一覧で押した行のSKUだけ、Amazon日本の「最大注文可能個数」を30にして、
Amazonの画面を開き直して30になったことまで確認します。

## 入れ替え方（Tampermonkey）

1. Tampermonkey のダッシュボードで「プライスター・購入上限30個」を開く
2. エディタ内で **Ctrl+A（全選択）→ Delete** で中身を空にする
3. `pricetar-max30.user.js` の中身を貼り付けて **Ctrl+S**
4. 同じ名前のスクリプトが2つ入っていないか確認する（あれば古い方を削除）
5. プライスターのページを再読み込みする

全選択せずに貼ると、スクリプトの中にもう1つ丸ごと入ってしまいます。
v1.0.5 で出ていた「別の購入上限処理が進行中です。このタブでは保存しません。」は、この二重貼りが原因でした。
v1.0.6 は二重に入っていても1回しか動かないようにしてあります。

## v1.0.7 の変更点

- 「［購入上限の入力］購入上限30の入力反映が12秒以内に完了しませんでした」で止まる問題への対策。
  欄に30と表示されても、Amazonが入力として受け取っていないことがありました。
  人がキーボードで打つのと同じ方法で30を入力し、だめなら従来の方法で入力します
- 打ち込む前に、選択されている欄が「最大注文可能個数」であることを確かめる（他の欄には打ち込まない）
- それでもAmazonが受け取らない場合は送信せずに止まり、欄の表示・中の値・元の値をメッセージに出す

## v1.0.6 の変更点

- 二重に貼られていても、1ページで1回しか動かない
- どの色のボタンでも、押せば「値を確認 → 30でなければ設定 → 開き直して確認」をやり直す
- 送信前にうまく進まなかったときは、画面を開き直して自動でやり直す（最大3回、送信はしない）
- 送信後は完了表示に頼らず、画面を開き直して30を確認する（約2分の間に最大4回）。
  それでも30にならなければ、30をもう1回だけ送信する
- Amazonのタブを閉じても、約90秒後には別の行を押せる（以前は最大10分ブロック）
- 止まったときは、どの段階か（［パネルの保存と照合］など）と、変わった項目名をメッセージに出す
- 価格など他の項目が変わったら送信しない、という安全確認は以前と同じ

ボタンの表示：
`購入上限30個`（未実行）／`確認・設定中…`／`30個 確認済 ✓`／
`反映待ち／押して再確認`（黄）／`エラー／押して再実行`・`中断／押して再開`（赤）

## テスト

Amazonとプライスターを真似た画面（`test/mock-*.html`）で、Chromium を使って動きを確かめます。
本物のAmazonの画面で確かめたものではありません。

```sh
node userscripts/test/run.cjs            # 全シナリオ（約3分）
node userscripts/test/run.cjs --nested   # スクリプトを二重に貼った状態で実行
```
